2.3 Security hardening

Supabase RLS (row-level security):

Profiles table: only auth.uid() = id can read/write self; admin role can update approval_status.

Logs table (if any): insert only via Edge Functions with service_role.

Edge Function verifyArtist: you already asked; keep it as source of truth flipping approval_status after heuristics (domain allow-list, presence, follower thresholds).

Auth tokens:

Do not use #access_token URL fragments as state in app; process once (hash catcher) → exchange/store session in Supabase client → immediately strip hash with history.replaceState.

CSP:

GitHub Pages can’t set headers; ship <meta http-equiv="Content-Security-Policy" ...> in apps/web/app/(marketing)/layout.tsx:

default-src 'self';
script-src 'self' 'wasm-unsafe-eval' 'nonce-__NONCE__';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
connect-src 'self' https://*.supabase.co https://*.ingest.*; 
frame-ancestors 'none';
base-uri 'self';
form-action 'self';


Generate a per-request nonce in a [server component layout] and inject into inline script tags only where needed.
